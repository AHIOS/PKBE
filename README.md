# PKBE

Proximity passkey activation POC. Living spec: [BLUEPRINT.md](BLUEPRINT.md).

Phase 1: Spring Boot relying party + iOS and Android apps.

Everything deploy-related is **environment-configurable** (no static `/.well-known` files). AASA and Asset Links are generated by the Spring controller from config.

## Configuration reference

| Env var | Purpose | Example |
| --- | --- | --- |
| `PORT` | HTTP listen port (Render injects this) | `8080` |
| `PKBE_PUBLIC_BASE_URL` | Public HTTPS URL after TLS termination | `https://pkbe.onrender.com` |
| `PKBE_RP_ID` | WebAuthn RP ID (hostname). Empty → host of public URL | `pkbe.onrender.com` |
| `PKBE_ORIGINS` | Comma-separated WebAuthn origins. Empty → public URL (+ `https://rp-id`) | `https://pkbe.onrender.com` |
| `PKBE_RP_NAME` | Display name | `PKBE` |
| `PKBE_APPLE_TEAM_ID` | Apple Team ID for AASA | `ABCDE12345` |
| `PKBE_IOS_BUNDLE_ID` | iOS bundle id | `com.uci.pkbe` |
| `PKBE_AASA_APPS` | Optional full AASA apps override | `ABCDE12345.com.uci.pkbe` |
| `PKBE_ANDROID_PACKAGE_NAME` | Android package (Asset Links) | `com.uci.pkbe` |
| `PKBE_ANDROID_SHA256_FINGERPRINTS` | Comma-separated cert fingerprints | `AA:BB:…` |
| `PKBE_REQUIRE_DEVICE_BOUND` | Reject BE=1 at registration | `false` |
| `PKBE_CHALLENGE_TTL_SECONDS` | Ceremony TTL | `120` |
| `MONGODB_URI` | Application logs only (`application_logs`). Must include the database name. Unset = console only | `mongodb+srv://…/pkbe` |
| `PKBE_LOG_TTL_DAYS` | Retention for `application_logs` | `14` |

Copy [server/.env.example](server/.env.example). Inspect a running instance:

```bash
curl -s https://YOUR_HOST/v1/public-config | jq
curl -s https://YOUR_HOST/.well-known/apple-app-site-association
curl -s https://YOUR_HOST/.well-known/assetlinks.json
```

`pkbe.rp-id` and the iOS Associated Domain host must be the **same hostname** as the public API.

## Local JVM

```bash
cd server
./gradlew bootRun --args='--spring.profiles.active=local'
```

- API: `http://localhost:8080`
- AASA: `http://localhost:8080/.well-known/apple-app-site-association`

## Tunnel (mole / localtunnel / ngrok / cloudflared)

TLS terminates at the tunnel; Spring stays on `localhost:8080`.

```bash
# terminal 1
cd server
./gradlew bootRun

# terminal 2 — example with cloudflared / mole / lt; use whatever gives you HTTPS
# lt --port 8080
# mole 8080
# cloudflared tunnel --url http://localhost:8080
```

Then restart (or start) Spring with the public URL:

```bash
export PKBE_PUBLIC_BASE_URL=https://YOUR_TUNNEL_HOST
export PKBE_APPLE_TEAM_ID=YOUR_TEAM_ID
./gradlew bootRun
```

Only `PKBE_PUBLIC_BASE_URL` is required for RP id / origins; they are derived from the URL host.

iOS: edit [ios/Configs/Tunnel.xcconfig](ios/Configs/Tunnel.xcconfig), point Debug at it (or swap `project.yml` Debug → Tunnel), then:

```bash
cd ios && xcodegen generate && open PKBE.xcodeproj
```

## Render.com

1. Push this repo to GitHub (already: `AHIOS/PKBE`).
2. In [Render Dashboard](https://dashboard.render.com) → **New** → **Blueprint** and select `AHIOS/PKBE` (uses `render.yaml`), **or** **Web Service** with:
   - Root directory: `server`
   - Runtime: Docker
   - Dockerfile path: `./Dockerfile`
   - Health check: `/health`
3. Env vars (minimum):
   - `PKBE_APPLE_TEAM_ID` = your Apple Team ID (required for real passkeys / AASA)
   - `PKBE_IOS_BUNDLE_ID` = `com.uci.pkbe` (default)
   - `MONGODB_URI` = Mongo connection string **including the database name**, if you want logs kept (Render free tier does not retain stdout). Users and ceremonies stay in memory.
   - Leave `PKBE_PUBLIC_BASE_URL` empty: Render injects `RENDER_EXTERNAL_URL`, which the app uses as the public base URL / RP ID source.

Logs land in `application_logs` whenever `MONGODB_URI` is set, and expire after `PKBE_LOG_TTL_DAYS` (default 14).
4. After deploy, check:
   - `https://<service>.onrender.com/health`
   - `https://<service>.onrender.com/v1/public-config`
   - `https://<service>.onrender.com/.well-known/apple-app-site-association`
5. Point iOS `Configs/Render.xcconfig` at the same hostname.

Render sets `PORT`; `application.yml` maps `server.port=${PORT:8080}`.

**iOS stays in this repo** under `ios/`. Android is under `android/`. Neither is part of the Render build (`rootDir: server`).

## iOS app

```bash
cd ios
xcodegen generate
open PKBE.xcodeproj
```

Build settings / Info.plist:

- `PKBERpId` ← `$(PKBE_RP_ID)` from xcconfig
- `PKBEBaseURL` ← `$(PKBE_BASE_URL)`
- Associated Domains: `webcredentials:$(PKBE_RP_ID)`

Configs:

| File | Use |
| --- | --- |
| `Configs/Local.xcconfig` | Simulator → localhost |
| `Configs/Tunnel.xcconfig` | Device + tunnel |
| `Configs/Render.xcconfig` | Device + Render |

1. Set your Development Team in Xcode.
2. Put a real Team ID in server env / AASA.
3. Use **two iPhones with different Apple IDs** for proximity (same iCloud can sync the passkey and skip BLE).

The iOS app has two tabs. **Native** uses `AuthenticationServices`. **WebView** loads `https://<rp-id>/webview/index.html` (same RP APIs via `navigator.credentials`). Passkeys in WKWebView require Associated Domains `webcredentials` for that host. The WebView tab keeps its own device id in page localStorage.

## Device walkthrough

1. Phone A: log in as `alice`, Enroll this device → `ACTIVE`.
2. Phone B: same username, Activate via nearby device (pending enroll + hybrid QR).
3. Scan QR with A, Face ID → B `ACTIVE`, A revoked.

**Refresh + reconcile:** the RP does not learn about Passwords deletions by itself. Pull-to-refresh (or **Refresh + reconcile Passwords**) loads `/v1/me`, probes whether this device still has `thisDeviceCredentialId` via `preferImmediatelyAvailableCredentials`, and calls `POST /v1/unenroll` when the key is gone. Until that runs, the **Server registry** section still shows the DB row.

## Android app

```bash
cd android
# JDK 17 or 21 (Gradle/AGP does not run on JDK 25)
./gradlew :app:assembleRenderDebug
# open android/ in Android Studio, flavor renderDebug
./gradlew :app:signingReport   # SHA-256 for Asset Links
```

Flavors (same idea as iOS xcconfigs):

| Flavor | Use |
| --- | --- |
| `local` | Emulator → `http://10.0.2.2:8080` |
| `tunnel` | Device + tunnel (edit host in `app/build.gradle.kts`) |
| `render` | Device + Render (`pkbe-nv4k.onrender.com`) |

Native tab uses Credential Manager (`CreatePublicKeyCredentialRequest` / `GetCredentialRequest`). WebView tab loads the same `/webview/index.html` page as iOS.

Passkeys need Digital Asset Links on the RP:

1. `./gradlew :app:signingReport` and copy the **SHA-256** of the debug (or upload) keystore.
2. Set on Render / env:
   - `PKBE_ANDROID_PACKAGE_NAME=com.uci.pkbe`
   - `PKBE_ANDROID_SHA256_FINGERPRINTS=AB:CD:…`
3. Confirm `https://<rp-id>/.well-known/assetlinks.json` lists that package + fingerprint (`get_login_creds` + `handle_all_urls`).

Without Asset Links, Android origin is `android:apk-key-hash:…` and the Spring RP (HTTPS origins only) will reject registration.

Emulator cannot prove hybrid QR. Use two physical devices (or Android + iPhone) with different Google/Apple accounts.
